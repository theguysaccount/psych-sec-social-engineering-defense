# Decisions

1. **Consumer self-test first, not B2B simulations.** The evaluator's fastest path was admin-authorized phishing simulations for companies. That needs client authorization, sending infrastructure, a server and sales, none of which a machine can run alone on GitHub Pages. The machine-runnable version of the same thesis ("psych sec > cyber sec", practice is the defense) is a public test. It also builds the audience and content the paid team version would sell to. Settles the open question "B2B or consumer first?": consumer first, team version as the paid key.
2. **Brand: "Spot the Scam", by Psych Sec.** "Psych Sec" stays as the maker. Searchers type "scam test" and "spot the scam", not "psych sec". Settles "is Psych Sec the brand?" as: the company brand, not the product name.
3. **Static site, Python build, no frameworks.** Python 3.9 is the only local runtime guaranteed; a stdlib generator plus plain ES modules has no dependencies to break or update. The message renderer exists in Python (build-time lesson pages) and JS (the test); a test requires identical output on every item.
4. **Content written once, rotated by alerts.** AI can't run in Actions, so 70 items and 25 lessons were written now, and the weekly job turns new FTC alerts into what gets featured. New items come from a scheduled Claude routine (key) working from `data/candidates.json` and `data/backlog.md`.
5. **Same test for everyone each week.** Seeded by ISO week, so a "challenge a friend" link and a parent's link replay exactly the same ten messages. "Take another test" uses a random seed.
6. **6 scams and 4 legit messages per test,** one scam per type, featured types first. A test of only scams teaches "say scam to everything"; the legit ones teach what real messages look like (they ask for nothing, match something you did, point you to the app you already use).
7. **Invented companies, fictional numbers, unregistered scam domains, dead links.** Real brands are named only where the FTC documents the impersonation (USPS, IRS, Social Security, FTC). Phone numbers use 555-0100–0199; every scam domain was checked to be unregistered (DNS) when written; links render as text. Tests enforce numbers, link markup and no `.gov` scam hosts.
8. **No analytics by default.** A scam-awareness site that tracks people undercuts itself. The event hooks are in the code and switch on with a GoatCounter key; until then the activation metric can't be measured, which is recorded in OPERATIONS.md.
9. **FTC + CISA feeds, CISA filtered hard.** CISA's feeds are mostly software vulnerabilities, so CISA items count only when the title is about scams or phishing. FTC alerts count when the title or summary is about scams.
10. **Archive seeded from the FTC alert listing.** The FTC feed carries only the newest 10 alerts. To make the alerts page and lesson pages useful on day one, 33 alerts from June–October 2026 were read from the FTC's public listing in a browser and merged once.
11. **No issues opened per new scam alert.** Most untagged FTC alerts are general advice; auto-opened issues would be noise. Candidates go to `data/candidates.json` and the run summary instead, for the routine to read.
12. **Hosting on GitHub Pages under the account URL.** No domain was owned for this idea. Candidates are listed in OPERATIONS.md; nothing was bought or pointed.
